Vibe: Technical MVP Speciﬁcation
Audience: an AI coding agent (Codex). Build the entire app described here from an empty
repository. Follow this document literally. Where a choice is not speciﬁed, pick the simplest
option that works and note it in the README.
1. Product Summary
AI can write code and layouts, but it has no taste. Users also cannot describe their aesthetic in
words ("make it modern and cool" is too vague). Vibe is a translation layer between human
intuition and machine execution.
The ﬂow:
1. The user expresses taste visually, by drawing on a canvas or uploading 1 to 3 reference
images.
2. The user answers about 10 rounds of text-free A/B image choices.
3. A vision-language model (VLM) reads all of those signals and outputs a strict JSON of
design tokens.
4. A script writes those tokens into the CSS variables of a pre-built dummy website, which
re-skins instantly without any change to its HTML structure.
The core demo claim: the human supplies the direction, the AI only executes the styling.
2. Hard Constraints
Local-ﬁrst. No cloud database, no S3, no Firebase, no auth, no deployment. Everything
runs on localhost.
Single repository. Images, dummy site, backend, and scripts all live in it.
Backend: Python 3.10+ with FastAPI, served by uvicorn. Frontend: plain HTML, CSS, and
vanilla JavaScript served as static ﬁles by FastAPI. No build step, no npm, no React.
One command starts everything: python start.py. It installs dependencies, launches
the server on http://localhost:8000, and opens the browser.
The app must work in a degraded mode with no API key (see Mock Mode in section 9), so
the demo never fails on stage.
The UI has no text in the A/B phase. Only images.

Server downscales images, calls the VLM with the baseline prompt (section 8.1), stores the
BaselineProfile in the session, and returns it. The frontend does not display the proﬁle text

Returns the latest tokens (from demo_site/vibe.json) or 404 if none.
POST /api/reset
Body: { "session_id" }. Clears the session and deletes demo_site/vibe.json. Also

Goal: 10 rounds, each an apples-to-apples pair from the same category, with contrast along a
clear aesthetic axis.
Rules:
Category order for rounds: start with baseline.preferred_categories, cycle through
all four categories so each is used at least twice (for example 3, 3, 2, 2 distribution).
Never show the same image twice in a session.
Within a category, choose pairs by contrast. Implementation for the MVP: if images have
tags, pick a pair with the fewest overlapping tags. If not, ask the VLM once at the start of

Mock Mode is on, pair randomly within the category using a seeded RNG.
Pair order on screen (which is left or right) is randomized.

9. Mock Mode
Triggered when ANTHROPIC_API_KEY is missing, or when the env var VIBE_MOCK=1, or when a
VLM call fails after retry.
You are a design token extractor. You convert a person's instinctive visual
choices into a strict JSON configuration for a website theme. You must only use
the allowed values. Respond with JSON only. No markdown, no commentary.
Rules:
- Winning images show what the person is drawn to. Rejected images show what to
avoid. Weigh winners and rejections together.
- Pick colors that appear in or are harmonious with the winners. Ensure text has
strong contrast against bg (WCAG AA or better).
- All enumerated fields must use exactly one of the allowed values.
- "rationale" must be 1 to 2 plain sentences linking specific choices (for
example "you picked concrete over glass, so I used sharp corners and hard
shadows") to the tokens.

12. One-Click Launch (start.py)
Behavior, in order:
1. Check Python version is 3.10 or higher, else print a clear error and exit.
2. Create .venv if it does not exist, then install requirements.txt into it (skip if a marker
ﬁle .venv/.installed matches the hash of requirements.txt).
3. If .env does not exist, copy .env.example and print a one-line note that Mock Mode
will be used unless a key is added.
4. If images/manifest.json is missing, run scripts/build_manifest.py. If the library is
empty, run scripts/fetch_sample_images.py.
5. Launch uvicorn backend.main:app --port 8000 as a subprocess using the venv
Python.
6. Poll /healthz until ready (max 20 seconds), then call
webbrowser.open("http://localhost:8000").
7. Forward Ctrl+C to cleanly stop the server.
run.sh: #!/usr/bin/env bash then python3 start.py. Make it executable. Also add
run.bat for Windows that calls python start.py.
Fail loudly with readable messages. If port 8000 is busy, try 8001 and open that instead.

16. Acceptance Criteria
The MVP is done when all of these are true:
python start.py on a fresh clone installs everything, starts the server, and opens the
browser with no manual steps.
Both Phase 1 paths (draw and upload) work and produce a baseline.
The A/B phase shows exactly 10 text-free rounds, each pair from the same category, no
repeated images.
Extraction returns valid VibeTokens JSON that passes schema validation and the
contrast check.
The demo site visibly re-skins (colors, fonts, radius, shadows, spacing, gradient) from the
tokens with no changes to its HTML.
Two different sessions with clearly different inputs (for example a neon dark sketch
versus a pastel organic moodboard) produce visibly different demo sites.
With no API key set, the entire ﬂow still completes in Mock Mode.
All tests pass with pytest.
Time from ﬁnal A/B click to re-skinned preview is under 15 seconds with the real VLM.
17. Out of Scope
User accounts, databases, cloud hosting, saving vibes across sessions, multi-page theming,
generating new layouts or components, and any CSS written by the model. The model only
chooses token values from the ﬁxed vocabulary.
